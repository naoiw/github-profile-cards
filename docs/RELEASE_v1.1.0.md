# GitHub Profile Cards v1.1.0

Compatible minor release of GitHub Profile Cards, the Node.js 26 / TypeScript CLI and GitHub Action for generating SVG language cards.

## Highlights

- **Browsable output gallery** (#19, #20): every generation writes `<output-dir>/README.md` alongside the SVGs, with inline previews grouped by theme. Cards use relative paths and show the selected chart type.
- **Latest-run listing**: the gallery references only cards generated by the current execution, excluding stale output files; unchanged Markdown is not rewritten.
- **SVG compatibility fix** (#17, #18): donut segments use explicit SVG arc paths rather than circle dash offsets, avoiding the browser-specific rendering artifact on small slices.

## Compatibility

- The existing Action inputs (`username`, `token`, `top-n`, `chart`, `theme`, `output-dir`, `hide-others`, `exclude-archived`, `exclude-repos`, and `exclude-languages`) are unchanged.
- Four SVGs remain at the same locations when `theme: all` is used. The additional `<output-dir>/README.md` is generated in the output root.
- `chart: donut` and `chart: bars` each select one chart layout per run; the gallery describes the actual generated style.
- The immutable `v1.0.0` tag continues to generate SVGs **without** the new gallery.

## Upgrade the calling workflow

After this release is published, pin this immutable version:

```yaml
- uses: naoiw/github-profile-cards@v1.1.0
  with:
    username: ${{ github.repository_owner }}
    theme: all
    chart: donut
    output-dir: profile-card-output
```

The calling workflow must commit the generated output (for example, `git add profile-card-output/`). On GitHub, browse `profile-card-output/` to view the gallery, then use a root-relative path such as `./profile-card-output/dark/languages-by-commit.svg` to embed the chosen card in a root README.

The `@v1` major alias is promoted **separately after testing the released Action** in an independent consumer repository; until then it can continue to point to `v1.0.0`. Callers pinned to `@v1.0.0` will not update automatically.

## Verification checklist

- Node.js 26 syntax, TypeScript, unit/CLI tests, and deterministic committed gallery checks.
- Real GitHub GraphQL data generation: all four SVG files and the root gallery README with valid relative references.
- Independent REST cross-check of public repository primary-language counts.
- **Post-publication:** invoke `uses: naoiw/github-profile-cards@v1.1.0` in a separate consumer repository; inspect the generated README in GitHub, verify commit/push and an idempotent rerun before promoting the major alias.

## Important limitations

- **By Commit** groups eligible GitHub commit contributions by each repository's primary language, not by languages changed inside commits.
- GitHub visibility and eligibility rules determine returned statistics. Private repository rows are excluded.
- No hosted API; generation requires GitHub Actions or a compatible Node.js 26 environment.
